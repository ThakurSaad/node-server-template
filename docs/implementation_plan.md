## 1. Overview

**Goal.** At the end of this plan:

- The server survives email, file and notification failures.
- Users can only reach their own data.
- Every request is validated at the edge.
- Passwords and OTPs are handled safely.
- `typecheck`, `lint:check`, `prettier:check` and `test` all pass.

**Principles**

- Make the smallest change that removes the real failure. Add no new libraries or layers: zod, validator, bcrypt and `node:crypto` are already installed.
- Keep the existing conventions:
  - `catchAsync` and `sendResponse`.
  - `ApiError` with `status` from `util/httpStatus`.
  - `validateRequest` with a `<module>.validation.ts` file written like `auth.validation.ts`.
  - `export =` for modules that export one value.
- v2's suggested fixes are a starting point. Where one was wrong or incomplete, the step is marked **Correction**.

**1.2 Make `unlinkFile` best-effort and confine it to `uploads/` (C1, C2).** Replace `src/util/unlinkFile.ts`:

```ts
import fs from "fs/promises";
import path from "path";
import { errorLogger } from "./logger";

const UPLOADS_DIR = path.resolve("uploads") + path.sep;

// Best-effort delete of an uploaded file. Never throws (a missing file must
// not fail the request, and an unhandled rejection stops the server) and
// never touches anything outside uploads/ (paths come from the database).
const unlinkFile = async (filePath: string): Promise<boolean> => {
  if (!filePath || !path.resolve(filePath).startsWith(UPLOADS_DIR)) {
    errorLogger.error(`unlinkFile: refusing to delete ${filePath}`);
    return false;
  }
  try {
    await fs.unlink(filePath);
    return true;
  } catch (error) {
    errorLogger.error(`unlinkFile: could not delete ${filePath}`, error);
    return false;
  }
};

export = unlinkFile;
```

## 5. Out of scope / later

- **Docker and CI** are deferred on purpose. When they come back, CI should run `typecheck → lint:check → prettier:check → test`, and the image must not copy `docs/openapi.yaml`.
- **Already handled or excluded:** C3 (already fixed), rewriting git history, and anything v2 already marks fixed.
- **Rate limiting:**
  - Limits are per IP and kept in memory. Running several instances needs a shared store such as Redis.
  - A per-email OTP throttle would stop email bombing from rotating IPs.
  - The limiters trust `trust proxy = 1`. Deployed without exactly one proxy in front, `X-Forwarded-For` is client-controlled and the limiters can be bypassed. Make `trust proxy` configurable at deploy time.
- **Token revocation:** a `tokenVersion` claim, if the 1-second `iat` window ever matters.
- **Account deletion** leaves the user's chats, messages, reviews and feedback behind.
- **Email templates:**
  - They hard-code the "Mount Fuji" branding and a personal contact address (`signUpEmailTemp.ts:81`).
  - `config.variables` (`EMAIL_TEMP_*`) is unused because the templates read `process.env` directly.
- **Test type-checking:** `tests/` is not covered by `npm run typecheck` (`include: ["src/**/*"]`). Consider a `tsconfig.test.json`.
- **WebSocket origins:** restricting them with Socket.IO's `allowRequest` would be defence in depth. The handshake already requires a JWT.
